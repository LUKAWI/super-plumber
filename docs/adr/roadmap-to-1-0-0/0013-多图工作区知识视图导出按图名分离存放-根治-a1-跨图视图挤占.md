# 0013 — 多图工作区知识视图导出按图名分离存放（根治 A1 跨图视图挤占）

多图工作区（.graph/ 下图数 > 1）中，export --docs 与 snapshot 自动导出的知识视图默认落按图名分离的目录：ADR → docs/<图名>/adr/NNNN-slug.md，context → docs/<图名>/contexts/<id>.md，CONTEXT-MAP → docs/<图名>/CONTEXT-MAP.md。单图工作区（含旧布局原地 default）保持现有路径 docs/adr、docs/contexts、CONTEXT-MAP.md 完全不变（向后兼容）。使用者显式传 --adr-dir/--ctx-dir 时优先于默认规则。实现集中在 src/core/docs-export.ts 的 runDocsExport 一处判定（listGraphNames > 1），snapshot 自动导出经同一函数自然继承，无需新参数、无需使用者配置。

**Status：** accepted

**Context：** v0.8.0 设计期实证（docs/v0.8.0-issue-log.md A1 + fix-v080-a1 cp1 复现）：ADR 编号按图独立（adr_NNNN 每图从 0001 起算），而 export --docs 与 snapshot 自动导出把知识视图落工作区共享目录（docs/adr/、CONTEXT-MAP.md、docs/contexts/）。多图工作区（本仓库现有 5 图并存）实测：roadmap 图导出把 default 图 3 个被跟踪的 ADR 视图挤进 docs/adr/.retired/ 并同号覆写，CONTEXT-MAP.md 随最后导出的图翻烧饼，docs/contexts/ 混装 4 张图的视图；反向导出同样互挤。snapshot 无 --adr-dir/--ctx-dir 透传，快照路径无法用现有选项隔离。retireStaleSlugFiles 的同号异名归档在共享目录语义下把其他图的有效视图误归档。

**Considered Options：** A. 工作区全局 ADR 编号账本：编号全局唯一避免同号冲突——但存放仍混装共享目录（CONTEXT-MAP/contexts 挤占未解决），需新账本文件、删除/迁移回收语义，复杂且不满足判据①，落选。B. 图名前缀编号（v080-0001）：文件名可区分但仍混装；id 格式破坏性变更冲击 schema 正则/decides 边/存量 ADR 迁移，使用者强感知，落选。C. snapshot 目录透传：仅补齐快照路径的隔离能力，仍要求使用者每次手动指定目录（强感知），且 CONTEXT-MAP.md 固定落工作区根、连 export 的 ctx-dir 透传都覆盖不到，单独作为方案落选。D（选定）. 多图工作区知识视图默认按图名分离：docs/<图名>/{adr,contexts,CONTEXT-MAP.md}，显式 --adr-dir/--ctx-dir 透传仍优先。

**Why：** 用户预授权判据（2026-08-30）：必须实现 ADR 按图名分离（直接分离存放最佳）+ 实现方法尽可能简单（对使用者无感最佳）。方案 D 是唯一"直接分离存放"的候选：物理隔离后同号覆写、.retired/ 误归档、CONTEXT-MAP 翻烧饼、contexts 混装四个症状同根消除；且零新参数零配置，单图行为不变，实现面集中在一个函数的目录前缀判定——简单性与无感性同时最优。

**Consequences：** ① 多图工作区根 CONTEXT-MAP.md 与 docs/adr、docs/contexts 不再被导出触碰（成为冻结的历史视图，迁移清理归发布节点）；② 各图视图目录内的文件可放心用 git 管理，.retired/ 归档只发生在图内语义正确的场景；③ 显式 --adr-dir/--ctx-dir 的既有缓解口径（如 g080-adr-promote 的隔离目录导出）不受影响；④ 若未来希望"跨图汇聚一份总视图"，需另做聚合导出（超出本 ADR 范围）；⑤ 既有使用者在多图工作区升级后视图落点变化——需要 CHANGELOG 注明（归发布节点）。
