# 0002 — 纯文件系统存储（无数据库）

所有数据以 YAML 文件形式存储在 `.graph/` 目录下。不使用关系型数据库、图数据库或任何其他持久化系统。Git 是版本控制的底层通道。

**Context：** 图拓扑数据可以存在多种后端中。图数据库（Neo4j）提供原生图遍历性能，SQLite 提供灵活查询，纯文件系统提供最简单的存储模型。

**Considered Options：**（1）Neo4j/图数据库 → 遍历快但引入重依赖，且 Git 无法对数据库做版本化；（2）SQLite → 查询灵活，但 `.graph/` 无法直接读作纯文本，也丧失了文件级 diff；（3）YAML 文件 + Git ← 选中的方案。

**Why：** 需求文档第一原则就是"Git 是唯一真相源"。文件方案让每个节点/边成为独立文件，Git 可以逐文件追踪变更，人类可以用编辑器直接修改，CI 可以对 `.graph/` 做 diff 检查。`index/` 下的派生索引（如 graph.json）可删除重建，不纳入版本控制。

**Consequences：**（1）复杂的跨节点查询（"找出所有下游 failed 且 upstream 包含 task_001 的节点"）需要在应用层遍历实现；（2）文件 I/O 是主要性能瓶颈，大规模图（>10000 节点）可能需要考虑索引优化；（3）保持了这个轮子零外部依赖的目标。
