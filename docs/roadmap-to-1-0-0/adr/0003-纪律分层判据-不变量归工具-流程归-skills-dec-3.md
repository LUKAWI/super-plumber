# 0003 — 纪律分层判据：不变量归工具，流程归 skills（DEC-3）

成文一条划分规则，指导未来所有“要不要强制”的争论：(a) 绕过会污染共享状态的 → 工具硬门禁，且硬门禁须同时满足：检查点与被管动作同址、报错一句话可恢复；(b) 只浪费自己功夫的绕过 → skills 纪律 + 工具关键时刻 nudge（adr_flags 式）；(c) 纯流程编排 → 只写 skills，工具不感知。现有三条硬门禁（ready 门禁 / passed 硬门禁 / max_attempts）全部符合 (a)，保留不动；设计审批归 (b)（DEC-1）。

**Status：** accepted

**Context：** 用户担心“约束过于强制会增大 agent 的 tool 调用出错率”。讨论确认该担心有技术依据：拦截分两类——拦住真越权是收益，拦住流程摩擦（agent 没错只是不知道规则）是纯损耗，且损耗正比于规则的隐蔽性与拒绝点的远近。

**Consequences：** 纯元规则，无直接实现；影响后续 feature 的论证方式。
