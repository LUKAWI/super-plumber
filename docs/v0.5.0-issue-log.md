## A. 代码缺陷（执行期发现并修复）

### A1. 索引缓存 Windows mtime"写后读"陈旧 【Mario 在 mcp 节点裁决中发现，已修复】
- **现象**：`tests/mcp/phase3.test.ts` 旧用例 flaky（ready 桶偶发为空）；同进程内 update-status 后 next-actions 仍返回旧状态。
- **根因**：`isFresh` 用"文件 mtime > builtAt(墙钟)"判缓存新鲜度。Windows NTFS mtime 系统性滞后 `Date.now()` 约 2ms——`updateNodeStatus` 内 `checkReadyGate`（写盘前）重建缓存刷新 builtAt，紧随其后的 `writeNode` 落盘 mtime 反而早于 builtAt → 缓存被误判新鲜，**同进程内永久陈旧**（100ms 后复测不自愈）。
- **归属**：Mario 以 git worktree bisect 判定为**预存缺陷**（core_runtime 提交前后均复现，3绿2红 vs 2绿3红），非 v0.5 引入；v0.5 的 governing_adrs 索引消费路径放大了暴露面。
- **修复**：fix_index_cache 节点——`invalidateIndex(rootDir)`（内存 Map 删除 + 磁盘 graph.json 删除），parser 全部变更原语（writeNode/writeEdge/writeGraph/deleteNode/deleteEdge/updateGraph）落盘后调用。确定性失效，不与文件系统时钟赌运气。
- **验证**：新增回归测试 3/3（同进程写后读立即可见）；phase3 复跑 5/5 全绿（此前 flaky 根治）。
- **附带**：parser ↔ index-service 形成函数级循环依赖（两侧仅函数体内互调，ESM 安全，已注释说明）。

### A2. `edgeMapsOf` 同类端点返回重复值 【自研测试抓出，已修复】
- 同为 workflow 的两端返回 `["workflow","workflow"]`——实现缺陷，改 Set 去重。

### A3. MCP supersede 两步法缺 `superseded_by` 参数 【写 E2E 时暴露的规格缺口，已补齐】
- super-mario 系统提示词承诺"先 graph_update_node {superseded_by} 再置状态"，但 `NodeUpdateParams`/MCP schema 均无该参数。补：core `superseded_by` 字段进 buildNodeUpdates + MCP graph_update_node 参数（两步法成立）。
